# 工作台控件统一与账号创建入口设计

日期：2026-08-10

状态：用户已批准开始实施

## 1. 问题

当前“易懂 / 专业”切换器已经形成明亮、圆角、紫色强调的视觉基线，但工作台内仍有原生浏览器下拉框、旧深色输入框和局部不一致的表单控件。它们不仅出现在顶部“全部平台 / 全部账号”，还散落在分析、导入、生成、风控、资产和设置页面。

账号创建 API 已存在，但新版账号列表只提供查看能力，工作区设置也只链接到账号列表。Admin/Editor 无法从常用位置发现“创建账号”，空账号状态也没有可执行入口。

## 2. 目标

1. 工作台范围内的文本输入、数字输入、搜索框、日期输入、文本域和下拉框采用同一套明亮专业视觉语言。
2. 原生下拉框不再显示突兀的系统灰色立体样式；选中、聚焦、禁用和错误状态仍清晰可辨。
3. 不把按钮、复选框、单选框、文件选择器和危险操作按钮粗暴改成同一种样式。
4. Admin/Editor 可在账号页创建抖音或小红书账号；Viewer 保持只读。
5. 创建入口至少出现在顶部账号范围旁、账号列表页和工作区设置页；空账号状态直接提供创建动作。
6. 创建完成后进入新账号仪表盘，并保留平台与账号 URL 范围。

## 3. 设计

### 3.1 控件基线

在 `WorkspaceShell` 根节点增加稳定范围标记，只在私有工作台内部应用统一表单样式。全局 CSS 通过该范围标记覆盖遗留页面中的文本类控件：

- 白色背景、浅色边框、12px 圆角、40px 最小高度。
- 主要文字使用 `--text-primary`，占位文字使用 `--text-secondary`。
- 聚焦使用 `--brand` 边框和浅紫色焦点环。
- 下拉框使用统一的紫灰色箭头，不依赖操作系统立体外观。
- 禁用态使用浅灰背景和明确的低强调文字，但保持可读。
- 旧 `bg-slate-950` 等局部类不再主导表单最终视觉。

不在 Demo、`/enter` 或非工作台页面上无边界覆盖。

### 3.2 账号创建

账号列表页加入内嵌创建面板，字段保持最小：平台、账号名称。目标、指标权重和动态基准使用产品默认值创建：

- 目标：`提升内容表现`
- 指标权重：`views = 1`
- 动态基准：最近 30 条

页面明确说明这些默认值可在账号建立后继续调整。提交使用现有 CSRF 和 `POST /v1/workspaces/{workspace_id}/accounts`，不新增 API 或数据库迁移。

成功后导航到 `/workspaces/{workspace_id}/accounts/{account_id}?platform={platform}&account={account_id}`。失败显示安全中文错误，保留用户已输入的名称以便重试。

### 3.3 入口与权限

- 顶部账号范围旁：Admin/Editor 显示“+ 创建账号”快捷入口。
- 账号列表页：Admin/Editor 页头显示“创建账号”；无账号时显示同一动作。
- 工作区设置页：Admin 显示“创建平台账号”。
- Viewer：不渲染上述写入口。

所有入口进入同一个账号页创建面板，避免维护多个表单。

## 4. 非目标

- 不修改账号创建 API、权限模型或数据库。
- 不增加平台授权、Cookie 抓取或平台账号自动同步。
- 不重新设计所有按钮和业务卡片。
- 不改变“易懂 / 专业”文案模式的行为。
- 不修改 Demo 或公开入口。

## 5. 验收

1. 工作台中遗留深色文本控件被明亮基线覆盖，原生 select 使用统一箭头。
2. 易懂/专业切换器与范围筛选在圆角、边框、焦点和品牌色上属于同一视觉体系。
3. Admin/Editor 能从顶部和账号页进入创建流程；Admin 还能从设置页进入。
4. Viewer 看不到创建入口。
5. 创建请求只发送固定安全默认值和用户选择的平台、名称。
6. 成功后进入新账号范围；失败可重试。
7. Web 测试、ESLint、TypeScript 和生产构建通过，并进行真实浏览器视觉复检。
