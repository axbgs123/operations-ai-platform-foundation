# 运营内容智能分析与生成平台：产品与系统设计

日期：2026-07-20  
状态：已完成需求讨论，等待用户复核书面设计  
目标优先级：秋招作品集 > GitHub 开源 > 真实团队长期使用

## 1. 产品定位

本产品面向 3—10 人的内容运营团队，首期服务抖音和小红书。产品将每次发布的标题、文案、封面、发布时间和运营数据沉淀为可复用的内容资产，通过动态基准、数据可视化、AI 内容分析、平台风控 RAG、账号风格继承和事实资料约束，形成以下闭环：

> 内容生产 → 发布记录 → 数据采集 → 动态分析 → 爆款确认 → 策略复用 → 新内容生成

产品首期是公开可访问的 Web 应用；后续可以增加桌面客户端和 App。浏览器扩展负责跨 macOS/Windows 的 Chrome/Edge 页面截屏与数据采集，未来桌面 Agent 复用相同后端能力。

## 2. 设计原则

1. 抖音与小红书的数据、指标、基准和评分完全分离。
2. 数据计算优先于大模型判断；AI 结论必须引用数据或知识来源。
3. 相关性不等于因果，分析只能给出原因假设和验证建议。
4. 事实资料的优先级高于风格模仿和爆款复用。
5. 平台风控使用确定性规则与 RAG 结合，不承诺内容必然通过审核。
6. AI 模型可替换；未配置模型时，内容库和基础数据分析仍可使用。
7. 开源仓库不包含真实运营数据、平台凭证、邀请码、模型密钥或私有 Prompt。
8. 使用模块化单体架构，避免过早拆分微服务。

## 3. 用户、访问方式与权限

### 3.1 公开体验区

- 无需注册或邀请码。
- 使用内置示例工作区和示例数据。
- 允许体验仪表盘、内容详情、分析报告和受限的生成流程。
- 禁止访问私有工作区。
- 限制数据修改、文件上传、AI 调用次数和资源消耗。

### 3.2 私有工作区

首期不建立个人账号体系，邀请码同时承担工作区凭证与权限凭证。邀请码不出现在 URL 中，服务端仅保存强哈希。

- 管理邀请码：管理工作区、平台账号、栏目、指标、模型、品牌风格、知识库、导入导出和删除操作。
- 成员邀请码：录入和导入数据、查看分析、使用 AI 生成；不能查看模型密钥或删除工作区。

验证成功后签发有过期时间的安全会话 Cookie。系统限制邀请码错误尝试次数，并允许管理员轮换或作废邀请码。查看者角色、个人账号和成员级审计属于后续扩展。

## 4. 数据层级与内容生命周期

### 4.1 数据层级

> 工作区 → 平台账号 → 栏目/活动 → 单条内容 → 数据快照

- 工作区之间完全隔离。
- 每个平台账号单独配置指标目标、权重和动态基准。
- 栏目或活动默认继承账号配置，可以临时覆盖。
- 单条内容保存发布时使用的配置版本，历史分析可复现。

### 4.2 内容生命周期

> 灵感/选题 → AI 生成 → 人工编辑 → 待审核 → 已发布 → 数据采集中 → 已分析 → 可复用

首期不自动发布到抖音或小红书，不做多标题、多封面的实验管理。每条内容保留当前草稿和最终发布版本。

## 5. 核心用户流程

1. 管理员进入私有工作区，创建抖音或小红书账号。
2. 配置账号默认目标、指标权重、动态基准、模型和账号风格。
3. 创建栏目或活动，需要时覆盖账号默认配置。
4. 通过手动、Excel/CSV、截图上传或浏览器扩展导入内容与数据。
5. 系统执行格式校验、去重预览和人工确认。
6. 内容与数据快照正式入库，系统自动更新动态基准和图表。
7. 用户手动触发 AI 深度分析；账号可选择新增快照后自动分析。
8. 系统推荐爆款候选，用户人工确认是否进入爆款素材库。
9. 用户进入生成中心，选择账号、栏目和运营目标。
10. 用户上传事实资料或选择无资料继续。
11. 已上传资料先提取事实清单并由用户确认。
12. 用户选择是否沿用历史风格（默认勾选）、爆款参考、生成预设和提示词。
13. 系统生成标题、文案和封面，随后执行事实一致性检查与平台风控检查。
14. 用户修改、确认并保存草稿；发布后再次录入数据，完成闭环。

## 7. 数据模型

### 7.1 组织与配置

- `workspaces`：工作区、状态和存储配额。
- `workspace_access_codes`：管理/成员邀请码哈希、状态和轮换时间。
- `platform_accounts`：平台、账号名称、账号标识和状态。
- `columns_campaigns`：栏目或活动、有效时间和覆盖配置。
- `objective_profiles`：指标优先级、权重、平台和版本。
- `benchmark_profiles`：最近 N 条、日期范围或全部历史等基准配置。
- `model_configs`：文本、视觉、图片生成和 Embedding 模型配置。

### 7.2 内容与指标

- `contents`：平台、账号、栏目、内容类型、标题、文案、封面、链接、发布时间、状态和来源。
- `content_assets`：封面、截图、参考图、文档和导出文件。
- `metric_definitions`：平台默认指标与工作区自定义指标。
- `data_snapshots`：采集时间、发布后时长、来源、原始截图和确认状态。
- `snapshot_metric_values`：指标定义、原始值、标准化值和识别置信度。
- `benchmark_runs`：比较范围、样本量、分位值、权重版本和计算时间。
- `analysis_runs`：输入快照、基准、模型、Prompt 版本、结果和错误状态。

### 7.3 爆款、生成与风格

- `viral_candidates`：系统推荐原因、分位和候选状态。
- `viral_library_items`：人工确认的爆款、策略标签、适用场景和结构摘要。
- `generation_sources`：上传资料、链接、联网来源和文字说明。
- `generation_runs`：平台、账号、栏目、事实清单、风格版本、爆款引用、提示词、模型和结果。
- `generation_presets`：模型、尺寸、提示词、参考图用途、文字区域、品牌元素和参数版本。
- `account_style_profiles`：标题、文案、封面风格及版本。
- `style_reference_contents`：人工选定的账号代表内容。
- `fact_sources`：文档、图片、链接和文字资料。
- `fact_items`：事实字段、值、来源位置、置信度、确认状态和冲突状态。

### 7.4 风控与系统任务

- `risk_documents`：平台、公共/私有、来源、发布日期、有效状态和版本。
- `risk_chunks`：文档分段、向量和元数据。
- `risk_scans`：扫描对象、规则版本、模型版本和总体结果。
- `risk_findings`：命中文字、封面区域、严重度、证据、来源和修改建议。
- `import_jobs`、`export_jobs`、`background_jobs`：任务状态、进度、错误和重试。
- `audit_logs`：工作区级关键操作。
- `deleted_items`：回收站和最终删除时间。

## 8. 平台指标与数据快照

### 8.1 抖音默认指标

- 播放量
- 点赞、评论、分享、收藏
- 2 秒跳出率、5 秒完播率、整体完播率
- 平均播放时长
- 主页访问、新增关注
- 发布时间和数据采集时间

### 8.2 小红书默认指标

- 曝光量、阅读/播放量
- 封面点击率
- 点赞、评论、收藏、分享
- 主页访问、新增关注
- 视频笔记平均观看时长和完播率
- 发布时间和数据采集时间

后台没有的字段允许为空。用户可以增加自定义指标。图文与视频内容分别建立基准。

### 8.3 快照规则

默认时间节点：发布后 1 小时、24 小时、72 小时、7 天，并支持自定义快照。每次录入新增快照，不覆盖旧数据。

自定义快照根据发布后时长映射到合理比较区间。1 小时数据不得与 7 天累计数据直接比较。

## 9. 动态基准与评分

1. 基准仅使用当前工作区的数据。
2. 必须同平台、同账号、同内容类型。
3. 用户可选择是否限定同栏目或活动。
4. 用户可选最近 N 条、指定日期或全部历史，默认最近 30 条。
5. 系统显示实际样本数和比较范围。
6. 少于 5 条只展示原始数据；5—9 条标记低置信度；10 条以上正常分析。
7. 使用中位数、前 25% 和前 10% 分位，不只使用平均值。
8. 先将不同指标转换为账号内历史分位，再依据目标权重计算综合评分。
9. 指标缺失时只对可用指标重新归一化权重，并明确提示缺失项。
10. 权重、样本范围和算法版本随分析记录保存，历史结果可复现。

“爆款”不是单一标签，系统可区分流量爆款、互动爆款、涨粉爆款和转化爆款。系统只推荐候选，进入爆款素材库必须人工确认。

## 10. AI 内容分析

基础指标自动计算，不依赖大模型。AI 深度分析默认由用户手动触发，账号可以开启新增快照后的自动分析。相同数据、基准、Prompt 和模型版本使用缓存。

分析步骤：

1. 读取当前快照、增长变化和动态基准。
2. 计算历史分位、异常指标、互动与转化派生指标。
3. 分析标题、文案结构和封面视觉。
4. 检索当前工作区中相似的高表现与低表现内容。
5. 输出结构化报告：数据表现、标题问题、文案问题、封面问题、证据、原因假设、置信度、改进建议和下一次实验。

系统不得把相关关系表述为确定因果；样本不足、数据缺失或内容条件不同必须降低置信度。

## 11. 账号风格继承

生成标题、文案和封面时，“沿用账号历史风格”默认勾选，三个内容类型可分别关闭。

账号风格档案包含：

- 标题长度、句式、钩子、常用词、标点和 Emoji。
- 文案语气、开头、段落结构、信息密度和行动引导。
- 封面配色、字体、字号层级、文字位置、Logo、构图和留白。
- 禁止使用的表达、颜色、版式和视觉风格。

风格样本由用户从已发布内容中人工选择。最近内容只用于辅助更新，爆款内容不自动成为品牌风格。账号风格支持版本化；栏目或活动可以临时覆盖，结束后恢复账号默认风格。

## 12. 事实资料与虚假宣传防护

生成前支持上传文档、图片、链接和文字说明，也支持联网搜索。用户资料是首选事实来源。

- 未上传资料：允许生成，但显示醒目的“无事实资料约束”提示。
- 已上传资料：OCR、文档解析和视觉模型先生成事实清单，用户确认后才能生成。
- 资料冲突：暂停生成，要求用户选择正确来源。
- 缺失信息：模型不得自行补充具体材质、参数、价格、功效或承诺。
- 结果核验：生成后再次与事实清单比对。
- 高风险冲突：阻止内容进入“待发布”状态。

以服装内容为例，事实清单可以包含产品名称、面料、颜色、尺码、版型、价格、活动、功能和适用场景。每项事实必须能够追溯到具体图片或文档位置。

生成约束优先级：

> 已确认事实资料 > 平台风控规则 > 账号/栏目风格 > 爆款结构参考

## 13. 风控 RAG 知识库

知识库分为：

- 系统公共库：抖音、小红书公开规则、官方说明和经过核验的公开案例。
- 工作区私有库：团队规范、历史违规案例、敏感词和审核经验。

抖音与小红书分别索引，并按照规则版本、发布日期和有效状态过滤。旧规则保留用于追溯，默认不参与当前扫描。

扫描节点：内容录入后、AI 生成后、发布前人工复检。

处理流程：

1. 封面 OCR 提取文字，与标题和文案合并为扫描对象。
2. 确定性规则检查明确的敏感词、联系方式和格式风险。
3. RAG 检索对应平台当前有效规则和相关案例。
4. 大模型只基于检索证据判断语境风险。
5. 输出风险类型、严重度、命中内容、规则引用、版本、原因、修改建议和复检结果。

用户上传的文档和检索内容均视为不可信数据，不能覆盖系统指令。风控结果必须提示“辅助判断，不保证通过平台审核”。

## 14. AI 生成中心

输入能力：

- 上传文档、图片和参考图。
- 粘贴链接。
- 联网搜索。
- 填写选题、要点和自定义提示词。
- 选择 0—3 条人工确认的爆款参考内容。
- 选择账号、栏目、目标和风格继承开关。

输出能力：

- 多个标题建议。
- 一份可编辑文案。
- 封面方案与最终封面。

封面生成模式：

1. 模板模式：替换标题、图片、Logo 和配色。
2. AI 视觉模式：模型生成背景或主体，程序叠加准确文字。
3. 混合模式：保留产品/人物，扩图、换背景后模板排版。
4. 自定义模式：自由选择模型、尺寸、参考图用途、提示词、文字和参数。

所有模式支持提示词和参考图。参考图需标注用途：构图、风格、人物、产品或配色。单次参数可以保存为团队生成预设。

程序负责中文文字排版，图片模型不负责生成最终文字。生成结果必须经过事实一致性检查和平台风控检查。

## 15. 数据导入、去重与导出

### 15.1 导入

支持：

- 手动逐条录入
- Excel/CSV 批量导入
- 手动上传截图识别
- 浏览器扩展采集截图

导入先进入暂存区，显示新增、更新、疑似重复和失败数量。用户确认后正式写入。

### 15.2 去重

- 优先使用“平台 + 账号 + 作品链接/作品 ID”。
- 没有链接时使用“发布时间 + 标题”提示疑似重复。
- 同一作品的新运营数据追加快照，不新建内容。
- 用户可以人工合并或保留为不同内容。
- 删除进入回收站，不直接永久删除。

### 15.3 导出与备份

- 内容与运营数据导出 CSV。
- 单条分析报告导出 Markdown。
- 工作区完整备份为 JSON。
- 封面、截图和参考图独立下载。
- JSON 备份可以恢复工作区。
- 删除工作区时同时删除结构化数据、向量和媒体文件。

## 16. 数据可视化

账号仪表盘提供：

- 指标卡：当前值、环比、历史分位和数据完整度。
- 折线图：单条内容和账号整体指标随时间变化。
- 基准线/区间：中位数、前 25% 和前 10%。
- 柱状图：不同栏目或内容的表现比较。
- 漏斗图：曝光 → 播放/阅读 → 互动 → 关注。
- 热力图：星期、发布时间和内容表现。
- 内容分布：普通、优秀、爆款候选和异常内容。

不同量纲默认不共用纵轴。抖音与小红书分别展示和计算。

## 17. 浏览器扩展与后续 Agent

首期通过 Chrome/Edge Manifest V3 扩展实现 macOS 和 Windows 的采集能力。

流程：

1. 用户在扩展中输入服务器地址和成员邀请码。
2. 服务端返回受限的短期令牌；扩展不长期保存原始邀请码。
3. 用户自行登录抖音或小红书创作者后台，打开单条作品详情页。
4. 用户点击“采集当前作品”。
5. 扩展确认域名与页面类型，自动滚动并截取必要区域。
6. 扩展不上传 Cookie、密码或浏览历史，只上传本次截图和必要元数据。
7. 视觉模型识别平台、内容标识和指标，低置信度字段留空。
8. Web 端展示识别结果，用户确认或修改后入库。

页面结构变化、验证码或识别失败时停止自动操作并要求人工处理，不尝试绕过平台安全机制。

后续桌面 Agent 和 App 使用相同后端 API。桌面 Agent 可以扩展到本地文件、桌面应用和更复杂的自动化，但不属于首期浏览器扩展范围。

## 18. 技术架构

采用单仓库、模块化单体：

- Web：React/Next.js。
- API：Python/FastAPI。
- 数据库：PostgreSQL，使用向量扩展存储风控知识向量。
- 对象存储：S3 兼容接口。
- 后台任务与缓存：Redis 队列。
- 浏览器扩展：Chrome/Edge Manifest V3。
- 部署：Docker Compose 本地一键启动，同时支持云服务器部署。

建议仓库结构：

```text
apps/
  web/
  api/
  extension/
packages/
  shared-schemas/
  model-adapters/
  platform-metrics/
infra/
  docker/
docs/
```

模块边界：

- Workspace：邀请码、会话与隔离。
- Content：账号、栏目、内容、媒体与状态。
- Metrics：指标定义、快照、动态基准与图表数据。
- Imports：手动、Excel、截图与扩展采集。
- Analysis：确定性计算与 AI 分析。
- StyleFacts：账号风格、事实来源与事实清单。
- RiskRAG：知识入库、检索、规则和扫描。
- Generation：文本、封面、预设和爆款引用。
- Exports：CSV、Markdown、JSON 备份与恢复。

业务规则在 API 层实现，不写死在 Web 页面，以便后续 App 和桌面客户端复用。

## 19. 模型适配与任务处理

管理员自带 API Key。文本生成、视觉理解、图片生成和 Embedding 可以使用不同供应商。

- 密钥在服务端加密保存，不返回前端，不写入日志。
- 供应商通过统一接口适配。
- Mock 模型用于公开体验和开源测试。
- 未配置模型时，AI 按钮显示配置提示，数据功能保持可用。
- AI、导入、生成、RAG 入库和导出均通过后台任务执行。
- 任务具有排队、运行、成功、失败、取消和重试状态。
- 相同输入、模型和版本可以复用缓存。

## 20. 安全与隐私

- 工作区查询必须携带工作区上下文，服务端二次校验资源归属。
- 邀请码使用强哈希，登录与 AI 接口限流。
- 管理会话与成员会话权限分离。
- 文件校验 MIME、扩展名、大小和访问权限。
- 媒体通过短期签名 URL 访问。
- 公开体验区使用独立工作区和独立资源额度。
- URL 抓取禁止访问本机、内网和云元数据地址，防止 SSRF。
- 上传文档、网页、截图和 OCR 文本不得作为系统指令执行。
- 日志不记录邀请码、API Key、完整敏感文案或未经脱敏的用户资料。
- 删除工作区需要管理权限与二次确认。

## 21. 异常处理与降级

- 数据缺失：保留空值，不猜测，不强制计算不适用指标。
- 样本不足：降低置信度或只展示原始数据。
- AI 超时/失败：保存原始数据，任务可重试，不阻塞内容使用。
- 识别置信度低：字段留空并要求用户确认。
- Excel 错误：逐行显示原因，确认前不写入正式表。
- 重复导入：显示合并预览，保持幂等。
- RAG 无有效证据：明确输出“未检索到有效规则”，不得编造引用。
- 资料冲突：暂停生成，要求人工选择。
- 对象存储失败：任务失败并保留可重试状态，数据库不写入失效地址。
- 扩展页面失配：停止采集，保留诊断信息并允许手动上传截图。

## 22. 测试策略

### 22.1 单元测试

- 平台指标隔离。
- 快照时间区间匹配。
- 中位数、分位数、综合评分和权重重分配。
- 账号/栏目配置继承和版本恢复。
- 去重与快照追加。
- 邀请码哈希与权限判断。
- 事实优先级和冲突判断。

### 22.2 集成测试

- Excel 导入预览、确认、错误行和回滚。
- 截图识别到人工确认入库。
- 风控知识入库、平台过滤、版本过滤与引用。
- AI 结构化输出异常、超时和缓存。
- JSON 备份和恢复一致性。
- 对象存储权限与删除。

### 22.3 端到端测试

- 公开体验区无法访问私有工作区。
- 邀请码进入工作区并完成核心流程。
- 导入内容 → 添加快照 → 动态基准 → AI 分析 → 爆款确认 → 新内容生成。
- 上传服装图片 → 提取面料事实 → 用户确认 → 生成内容 → 事实与风控复检。
- 浏览器扩展在抖音、小红书测试页面完成截图采集。

### 22.4 关键不变量

- 抖音与小红书绝不混算。
- 不同工作区数据绝不串用。
- 不同账号风格绝不串用。
- 未确认事实不得进入受事实约束的生成。
- 爆款参考不得覆盖事实和风控规则。
- 关闭风格继承后不得隐式引用历史风格。

## 23. 开源交付要求

仓库必须包含：

- README 与产品截图
- 架构和数据模型说明
- 环境变量示例
- Docker Compose 一键启动
- 数据库迁移与示例工作区
- Mock 模型与 Mock 截图识别
- 浏览器扩展安装说明
- 备份与恢复说明
- 贡献指南、行为准则和安全报告方式
- 许可证文件

开源示例数据应是人工生成或获得授权的数据。公共风控知识库必须保存来源和版本，不打包版权不明确的资料。

## 24. 明确不做

- 首期不自动发布抖音或小红书内容。
- 不保存或代填平台账号密码。
- 不保存 Cookie，不绕过验证码或平台权限。
- 不通过非官方隐藏接口批量抓取数据。
- 不保存完整视频和小红书全部原图；只保存封面、截图、参考图和作品链接。
- 不做严格 A/B 实验系统。
- 不把 AI 风控结果宣传为平台审核保证。
- 不把公开体验区数据与私有工作区混合。

## 25. 验收定义

一个完整可用版本至少应满足：

1. 无邀请码访客可以安全体验示例工作区。
2. 管理/成员邀请码能正确进入隔离的私有工作区。
3. 抖音和小红书可以分别创建账号、栏目和指标配置。
4. 手动、Excel、截图和浏览器扩展可以完成内容及快照导入。
5. 动态基准能按平台、账号、内容类型、时间节点和用户范围正确计算。
6. 仪表盘能展示折线图、分位基准、栏目表现和爆款候选。
7. AI 分析引用实际数据，样本不足时正确降级。
8. 风控 RAG 能返回当前平台有效规则、来源和修改建议。
9. 账号风格默认继承，并可按标题、文案、封面分别关闭。
10. 上传资料后必须确认事实清单，生成结果不能添加未确认参数。
11. 爆款内容只有人工确认后才能进入素材库并被引用。
12. 标题、文案和四种封面模式可以完成生成和保存。
13. CSV、Markdown、JSON 与媒体导出可用，JSON 可以恢复。
14. AI 或识别任务失败时不破坏已保存数据。
15. 项目可以依据文档在新环境中完成部署，仓库不包含秘密与真实私有数据。
