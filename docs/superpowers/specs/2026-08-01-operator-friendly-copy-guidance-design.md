# 运营人员友好文案与常驻引导设计规格

日期：2026-08-01

状态：设计完成，等待用户复核书面规格

产品基线：

- `docs/superpowers/specs/2026-07-20-operations-ai-platform-design.md`
- `docs/superpowers/specs/2026-07-29-workbench-frontend-redesign-design.md`
- `docs/superpowers/specs/2026-08-01-two-level-workbench-navigation-design.md`

## 1. 背景

新版工作台已经解决主要功能入口过多、导航层级不直观的问题，但非开发者体验仍存在两个明显障碍：

1. 页面说明大量使用产品、数据和工程术语，运营人员需要先理解系统概念，才能判断功能有什么用。
2. 一些页面只有标题、状态和按钮，缺少“这里能做什么”和“下一步怎么做”的持续说明。

目标用户是内容运营、编导和 AIGC 内容从业者，不应要求其理解系统实现方式。默认界面应使用运营工作中的自然语言；需要审计或深入判断时，用户仍可切换到专业模式查看原有精确信息。

本次只调整界面文案、说明层级和浏览器端展示偏好，不修改业务规则、权限、数据、接口结论或安全门禁。

## 2. 设计目标

1. 新用户进入任何正式模块后，十秒内能理解“这里能做什么”和“建议先做什么”。
2. 默认文案使用运营人员常用说法，不暴露没有必要的开发术语。
3. 原有专业文案不删除，统一保留在专业模式。
4. 页面引导不是一次性新手弹窗，可随时开启、关闭和重新查看。
5. 易懂模式不能通过简化文字掩盖风险、证据不足、数据缺失或权限限制。
6. Admin、Editor、Viewer 看到的下一步建议必须符合其真实权限。
7. 桌面端和移动端都能访问文案模式与页面引导。
8. 不新增 API、数据库迁移、第三方组件库或在线字体。

## 3. 非目标

1. 不修改分析、生成、风控、事实、导入或备份的业务算法。
2. 不重写服务端错误合同和审计记录。
3. 不隐藏必要的风险免责声明。
4. 不把所有专业词替换成不准确的口号。
5. 不提供遮挡页面的强制漫游教程。
6. 不增加只在首次访问时出现、关闭后无法恢复的引导。
7. 不向 Viewer 展示其无权执行的按钮或操作建议。
8. 不在本阶段接入埋点实验或远程偏好同步。

## 4. 已批准的体验方案

采用两个互不依赖的顶部控制：

1. 文案模式：`易懂` / `专业`
2. 页面引导：`开` / `关`

默认值：

- 文案模式：易懂
- 页面引导：开

页面采用紧凑的内嵌引导，不使用固定右侧栏：

1. 页面标题下始终保留一句用途说明。
2. 引导开启时，继续显示“建议先做什么”。
3. 需要更多帮助时，可展开“查看操作说明”。
4. 详细说明包含操作步骤、页面概念和常见卡点。

即使关闭页面引导，一句话用途说明仍然保留，避免页面退回到“只有标题和按钮”的状态。

## 5. 核心文案原则

### 5.1 默认说运营结果，不说系统实现

易懂模式优先回答：

1. 这里能帮我做什么？
2. 我需要准备什么？
3. 结果会保存到哪里？
4. 现在为什么不能继续？
5. 下一步应该点哪里？

默认不解释：

- 使用了哪种内部检索或模型链路。
- 数据表、队列、状态机和 Worker 如何运作。
- API、Schema、向量或对象存储实现。
- 幂等、Fencing、RAG、Mock 等工程概念。

只有当这些信息会影响用户判断时，才转译为运营语言；原术语留在专业模式或详细说明中。

### 5.2 能用一句话说清楚，就不用专业名词

示例：

| 原说法 | 易懂模式 | 专业模式 |
| --- | --- | --- |
| 动态基准 | 和这个账号最近的同类作品比较 | 动态基准 |
| 数据成熟度 24h | 这是发布 24 小时后的数据 | 数据成熟度：24h |
| 置信度不足 | 当前判断把握不高，建议人工检查 | 低置信度 |
| Evidence | 本次判断参考了哪些数据和资料 | Evidence / 证据引用 |
| 发布门禁未通过 | 还有必须处理的问题，暂时不能标记为可发布 | 发布门禁未通过 |
| 暂存预览 | 数据还没有正式导入，请先检查并确认 | 暂存预览 |
| OCR 低置信度 | 图片里的文字可能识别不准，请人工检查 | OCR 低置信度 |
| RAG 辅助判断 | 系统参考了已保存的平台规则资料 | RAG 辅助判断 |
| Mock 模式 | 当前是模拟体验，不调用真实模型，也不会产生模型费用 | Mock 模式 |
| configuration_required | 还没有完成所需配置，请联系管理员 | 配置状态：configuration_required |
| compensation_required | 自动清理没有完成，需要管理员处理 | 补偿状态：compensation_required |

### 5.3 不翻译用户不需要知道的内部状态码

默认页面不得直接把以下内容当作主要文案：

- 英文错误码。
- 数据库或任务状态枚举。
- 模型合同名称。
- Provider 请求细节。
- 内部版本号。

易懂模式显示“发生了什么”和“怎么处理”；专业模式在不泄露敏感信息的前提下补充原状态码、版本和技术名称。

### 5.4 关键风险不能被弱化

以下信息在两种模式下都必须保留，只改变表达方式：

- 高风险内容被阻止。
- 图片文字识别失败或不可靠。
- 没有有效规则资料。
- 数据样本不足。
- 事实冲突或未经确认。
- 真实模型可能产生费用。
- 删除、恢复和覆盖的影响。
- “辅助判断，不保证通过平台审核”等固定免责声明。

易懂模式不能把“高风险”改写成“可能需要关注”等含糊说法。

### 5.5 不用空泛营销话术

禁止使用：

- “赋能运营增长”
- “智能化提升效率”
- “打造闭环生态”
- “全链路解决方案”
- “一站式能力”

替换为具体结果，例如：

- “把已发布作品和数据放到一起查看。”
- “找出表现变差的环节，并保存下一步建议。”
- “生成标题、文案和封面前，先核对事实和账号风格。”

## 6. 两种文案模式

### 6.1 易懂模式

面向默认运营用户。

规则：

1. 使用日常运营词汇。
2. 句子尽量控制在一层因果关系。
3. 按钮使用动作加对象，例如“导入作品数据”“检查发布风险”。
4. 状态后给出可执行说明，例如“缺少数据：先导入一次发布后的表现数据”。
5. 必要术语第一次出现时使用“易懂解释（专业名词）”形式，后续只显示易懂解释。
6. 不出现实现原理，除非会改变用户选择或费用。

### 6.2 专业模式

面向产品复核、审计、排障和熟悉系统的用户。

规则：

1. 保留现有已验证专业文案和状态名称。
2. 显示分析版本、证据等级、置信度、模型模式和安全状态等原有信息。
3. 不因为专业模式而显示密钥、敏感正文或服务端禁止返回的信息。
4. 不改变按钮权限和业务结果。

### 6.3 切换行为

1. 切换后只更新当前页面展示，不发起业务写操作。
2. 不改变筛选、分页、表单内容、草稿或当前步骤。
3. 不影响另一项“页面引导”开关。
4. 刷新和重新进入工作区后保持该成员的选择。

## 7. 常驻页面引导

### 7.1 关闭状态

页面标题下只显示一句用途说明，例如：

> 把已发布作品、运营数据和分析结果放在一起管理。

该说明不能省略，也不能使用“内容资产统一管理中心”一类抽象说法。

### 7.2 开启状态

标题区域下方增加紧凑引导：

- `这个页面能做什么`：一句具体用途。
- `建议先做`：当前角色可执行的一项行动。
- `查看操作说明`：可展开的详细帮助。

不使用大型欢迎卡片，不挤占首屏主要数据，不建立固定右侧栏。

### 7.3 展开说明

详细帮助包含：

1. `怎么使用`：最多 3—5 个步骤。
2. `你会看到什么`：只解释页面中必须理解的概念。
3. `常见情况`：说明无数据、无权限、配置缺失、样本不足等处理方式。

每条说明先给运营语言。专业模式可在同一位置补充专业术语，但不重复整段内容。

### 7.4 角色差异

Admin：

- 可以看到配置、审核、恢复和治理建议。

Editor：

- 可以看到导入、分析、生成、确认和反馈建议。
- 不提示模型密钥、成员权限或删除工作区等管理员操作。

Viewer：

- 只提示查看、筛选、比较和下载已允许结果。
- 如果下一步需要更高权限，说明“请联系管理员或编辑者”，不展示不可执行按钮。

## 8. 页面文案目录

所有 16 个正式模块入口及关键详情页使用统一目录管理，不在页面组件中散落大量条件表达式。

每个页面条目至少包含：

- 页面标识。
- 易懂用途说明。
- 专业用途说明。
- 按角色区分的下一步建议。
- 3—5 条操作步骤。
- 需要解释的页面概念。
- 常见卡点和处理方法。

### 8.1 总览

#### 工作台总览

易懂用途：

> 看清各账号目前缺什么数据、有哪些待处理内容，以及现在最值得先做哪一件事。

避免使用：

- 北极星指标
- 有效闭环归因
- 跨平台聚合视图

如需展示闭环，易懂模式写成：

> 本周是否完成“发布作品 → 录入数据 → 查看分析 → 采取行动”。

### 8.2 运营

#### 内容库

> 集中查看每条作品、发布状态、数据、分析和风险结果。

#### 数据导入

> 把作品和发布后的运营数据录入系统；确认前不会写入正式记录。

#### 分析中心

> 找出还没分析或分析失败的作品，并查看问题和改进建议。

#### 账号仪表盘

> 只看一个账号的表现变化、目标完成情况和异常内容。

#### 栏目与活动

> 管理账号平时使用的栏目规则，以及活动期间临时使用的规则。

### 8.3 创作

#### 生成中心

> 根据已确认的事实、账号风格和参考内容，生成标题、文案和封面。

#### 发布前检查

> 集中检查准备发布的内容，处理风险、图片文字识别和资料不足问题。

### 8.4 资产

#### 爆款素材库

> 保存确认过的优秀内容结构，之后生成内容时可以继续参考。

#### 账号风格

> 保存每个账号常用的标题、文案和封面风格，避免不同作品风格跳动太大。

#### 事实资料

> 保存商品、活动或选题中可以确认的事实，生成内容时用它减少写错和虚假宣传。

### 8.5 管理

#### 导出与备份

> 导出运营数据和分析报告，或备份整个工作区后再恢复。

#### 后台任务

> 查看导入、分析、生成、备份等耗时任务有没有完成，失败后该怎么处理。

#### 风控知识库

> 管理平台规则资料，审核后才会用于内容风险检查。

#### 回收站

> 恢复还在保留期内的内容；工作区永久删除在设置中单独处理。

#### 工作区设置

> 管理成员、邀请码、账号、模型配置、费用限制和工作区安全操作。

## 9. 状态、按钮与空页面

### 9.1 状态写法

默认格式：

> 结果 + 原因 + 下一步

示例：

- `还不能分析：这条作品没有已确认的数据。先导入并确认一次数据。`
- `图片文字可能识别不准：请核对封面中的商品名、价格和功效描述。`
- `暂时没有可用的平台规则资料：确定性规则仍会继续检查，但建议人工复核。`

专业模式可以追加：

> 状态码：NO_ACTIVE_RISK_EVIDENCE

### 9.2 按钮写法

按钮必须表达动作和对象。

推荐：

- `导入作品数据`
- `确认并正式写入`
- `重新检查风险`
- `保存为爆款参考`
- `查看失败原因`

避免：

- `处理`
- `继续`
- `执行`
- `提交`
- `确认`

只有上下文已经完全明确时，才允许使用短按钮。

### 9.3 空页面

空页面不得只显示“暂无数据”。

必须说明：

1. 当前缺少什么。
2. 为什么这里需要它。
3. 有权限的用户下一步可以做什么。
4. 无权限用户应该联系谁。

例如：

> 还没有已确认的作品数据。导入一次发布后的数据后，这里会显示表现变化和分析建议。

## 10. 组件与状态设计

### 10.1 展示偏好

在 `WorkspaceShell` 范围内提供统一展示偏好：

- `copyMode: "simple" | "professional"`
- `pageGuidance: "on" | "off"`

浏览器本地键按成员隔离：

- `operations-ai:copy-mode:{memberId}`
- `operations-ai:page-guidance:{memberId}`

规则：

1. 缺失、非法或旧值回退到 `simple` 和 `on`。
2. 不保存业务正文、Prompt、图片、邀请码、Token或工作区数据。
3. 成员退出或会话失效时，只按现有安全策略处理对应展示偏好，不读取其他成员值。
4. Demo 使用独立固定身份键，不与私有成员偏好混用。

### 10.2 顶部控制

新增统一 `ExperienceControls`：

- 易懂 / 专业
- 引导开 / 关

桌面端位于右上角成员区域附近。

移动端放入顶部可访问的紧凑菜单中，不能只藏在侧栏深处。

控制必须具备：

- 明确文字标签。
- 键盘焦点。
- 当前选择状态。
- 屏幕阅读器可访问名称。
- 不能只依赖颜色表达状态。

### 10.3 页面引导组件

统一 `PageGuide` 负责：

- 一句话用途。
- 下一步建议。
- 展开和收起详细说明。
- 根据文案模式切换内容。
- 根据角色隐藏无权操作。

`PageHeader` 继续负责页面层级和标题；`PageGuide` 不复制面包屑或页面主标题。

### 10.4 文案目录

集中目录固定拆分为：

- `operator-copy-catalog.ts`
- `page-guidance-catalog.ts`
- `experience-preferences.ts`

页面只通过稳定页面标识读取文案。禁止每个页面自行判断模式并堆叠三元表达式，以免易懂文案、专业文案和权限提示逐渐漂移。

API 返回的业务数值、证据和状态仍是权威来源。目录只决定如何展示，不修改、猜测或补全服务端结果。

## 11. 数据流

1. `WorkspaceShell` 获取当前成员和角色。
2. 展示偏好 Provider 读取该成员的浏览器本地偏好。
3. 当前路由映射到稳定页面标识。
4. 文案目录返回易懂或专业用途说明。
5. 引导目录根据角色返回合法的下一步与详细说明。
6. 页面业务组件继续使用原 API 数据。
7. 状态展示组件将服务端结果映射为对应模式的标签和解释。
8. 用户切换模式时，仅重新渲染展示文本。

文案模式不得改变 API 请求参数、权限判断、排序、筛选、生成 Prompt 或保存内容。

## 12. 错误与降级

1. 文案目录缺少条目时，开发和测试环境明确报错；生产环境回退现有专业文案，不能显示空白。
2. 浏览器存储不可用时，本次会话使用默认 `易懂 + 引导开`，页面功能继续运行。
3. 当前角色没有合法下一步时，只显示用途和权限说明，不伪造行动。
4. API 错误继续使用现有安全错误边界；易懂模式不得展示异常详情或供应商原始错误正文。
5. 页面数据加载失败时，引导仍可显示，但不能根据缺失数据猜测状态。
6. 未知服务端状态在易懂模式显示“当前状态暂时无法识别，请刷新或联系管理员”，专业模式附带安全的原状态值。

## 13. 测试与验收

### 13.1 单元和组件测试

1. 默认值为易懂模式、引导开启。
2. 两项控制互不影响。
3. 偏好按成员隔离并能在刷新后恢复。
4. 非法本地存储值安全回退。
5. 16 个正式模块均具备用途说明、专业文案和角色建议。
6. Viewer 不收到写操作建议。
7. 关键风险在两种模式下都不会消失。
8. 关闭引导后仍显示一句用途说明。
9. 按钮、空页面和错误状态使用运营人员可理解的表达。
10. 未知目录项不会渲染空白。

### 13.2 E2E

1. Admin、Editor、Viewer 分别验证顶部控制和角色化建议。
2. 在易懂与专业模式间切换，页面数据、筛选和表单状态不变化。
3. 刷新、前进、后退和跨模块跳转后偏好保持。
4. 390px 下可访问顶部控制、展开引导并关闭。
5. Demo 与私有成员偏好隔离。
6. 工作台、内容库、数据导入、生成中心、发布前检查、后台任务至少各完成一条端到端文案验收。

### 13.3 视觉回归

至少覆盖：

- 桌面：易懂开、易懂关、专业开。
- 移动：易懂开、专业关。
- 长文案、空页面、错误状态和 Viewer 权限说明。

引导区域不能推开首屏核心操作到不可见位置，不能产生固定右侧空栏，也不能遮挡移动端内容。

### 13.4 非开发者验收

在重新开始 Task 9B 前，给未参与开发的运营型参与者完成以下任务：

1. 不看开发文档，说明任意页面“能做什么”。
2. 找到系统建议的下一步。
3. 关闭和重新开启页面引导。
4. 切到专业模式查看原术语，再切回易懂模式。
5. 遇到空数据、权限不足和低置信度状态时，说出下一步处理方法。

记录：

- 首次理解时间。
- 需要主持人解释的词。
- 找不到的操作。
- 错误理解的风险或权限。

## 15. 与既有设计的符合性复查

### 15.1 原始产品设计

- 不改变“数据导入 → 分析 → 建议 → 生成 → 风控 → 发布后复盘”的核心运营流程。
- 不混算抖音和小红书指标。
- 不削弱事实资料、账号风格、爆款参考和平台风控的边界。
- 不把 AI 辅助判断描述为保证。
- 不改变邀请码工作区、角色权限和 Demo 隔离。

### 15.2 工作台重设计

- 保持工作区、账号、栏目、内容的稳定层级。
- 保持共享 WorkspaceShell、Scope 和安全 `returnTo`。
- 保持桌面完整、移动轻量的能力边界。
- 不改变 16 个正式模块和规范路由。

### 15.3 双层导航

- 不改变五个大类和小类归属。
- 顶部体验控制不挤入一级大类栏。
- 页面引导位于主内容区，不形成第三层导航。
- 390px 下沿用现有两步抽屉，体验控制放在顶部紧凑菜单。

## 16. 完成标准

满足以下条件才可判定完成：

1. 16 个正式模块均有易懂和专业文案。
2. 默认用户不需要理解开发术语即可说出页面用途。
3. 页面引导可随时开启、关闭和重新查看。
4. 两项偏好按成员隔离并安全降级。
5. Viewer 不出现不可执行操作建议。
6. 风险、证据不足、数据不足和权限限制没有因简化文案而被弱化。
7. API、数据库、权限和业务规则无意外变化。
8. 全量自动化、E2E、移动端和视觉回归通过。
9. 书面文案目录通过逐页人工复检。
10. 独立非开发者能够在没有主持人代操作的情况下理解主要页面和下一步。
