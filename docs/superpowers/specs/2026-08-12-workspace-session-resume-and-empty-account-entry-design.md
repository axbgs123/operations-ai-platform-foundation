# 工作区会话恢复与空账号入口设计

日期：2026-08-12

状态：用户已批准实施

## 1. 问题

团队及会话记录在 Docker 重启后仍保存在 PostgreSQL，但 `/enter` 只提供“创建团队”和“加入团队”，不会识别同一浏览器中仍有效的会话。用户重新打开入口时容易误以为原团队已丢失，并可能重复创建团队。

工作台总览在没有抖音或小红书账号时虽然提供“配置平台账号”，但该按钮跳转到通用设置，未直接打开已有的账号创建面板，文案也不如“创建账号”直观。

## 2. 目标

1. 同一浏览器中，只要 14 天会话 Cookie 仍有效，重新打开 `/enter` 或重启本地服务后自动返回原团队。
2. 会话失效、成员被撤销或工作区不存在时，安全清理本机恢复记录，再显示创建/加入入口。
3. 临时网络故障不能把有效恢复记录当作失效记录删除，也不能诱导用户重复创建团队。
4. Admin/Editor 在无平台账号的工作台首页看到明确的“创建账号”按钮，并直接进入账号创建面板；Viewer 继续只读。
5. 不删除、合并或猜测任何已有团队，不改变邀请权限和工作区隔离规则。

## 3. 方案比较与选择

### 方案 A：浏览器恢复记录并由服务端验证（采用）

创建或加入团队成功后，在浏览器保存一个版本化恢复记录，仅包含 `workspace_id`、`member_id` 和 CSRF Token。`/enter` 读取记录后，使用现有 HttpOnly Session Cookie 调用工作区上下文接口验证；验证通过才返回原团队。

优点：不新增数据库迁移和认证接口；不会旋转会话或破坏其他标签页；能够复用现有工作区隔离和成员撤销检查。CSRF Token 本身不能脱离 HttpOnly Session Cookie 完成认证。

缺点：只解决同一浏览器恢复，不支持清 Cookie、无痕模式或跨设备找回。

### 方案 B：新增服务端会话恢复接口（暂不采用）

入口凭 Session Cookie 重新签发 CSRF Token。服务端边界更集中，但现有数据模型每个 Session 只保存一个 CSRF 哈希，重新签发会使其他已打开标签页的写操作失效；完整解决需要多 Token 模型或迁移，超出本次问题范围。

### 方案 C：账号密码或管理员恢复码（暂不采用）

能够支持跨设备找回，但会引入新的长期凭证、恢复流程和安全责任。本次先修复已确认的同浏览器重启问题，跨设备恢复另立设计。

## 4. 会话恢复设计

新增单一浏览器侧会话恢复模块，统一负责：

- 使用固定版本键保存恢复记录。
- 严格校验 UUID、成员 ID 和 CSRF Token；未知版本、损坏 JSON 或多余字段一律忽略并清理。
- 创建团队和邀请码加入成功后，同时写入当前标签页 CSRF 状态和浏览器恢复记录。
- `/enter` 初次加载时若存在恢复记录，先显示“正在返回上次团队”，将 CSRF Token 恢复到当前标签页，再调用现有 `GET /v1/workspaces/{workspace_id}/workbench/context`。
- 服务端返回成功且 `workspace_id`、`member_id` 与记录完全一致时，跳转到原工作台。
- 返回 `401` 或 `404` 时，清理恢复记录和当前标签页 CSRF，再显示创建/加入入口。
- 网络错误或依赖故障时保留恢复记录，显示“返回上次团队”重试动作，并允许用户明确选择继续创建或加入；不自动创建新团队。
- Workspace Shell 后续遇到 `401` 时也清理恢复记录，避免入口反复尝试失效会话。

恢复记录不包含 Session Cookie、邀请码、名称、业务正文、模型密钥或平台数据。真正的认证凭证仍是服务端设置的 HttpOnly Cookie。

## 5. 空账号首页入口

当工作台总览没有平台账号时：

- Admin/Editor 显示主按钮“创建账号”。
- 按钮直接进入 `/workspaces/{workspace_id}/accounts?action=create`，打开现有 `AccountCreatePanel`。
- 顶部“＋ 创建账号”快捷入口继续保留，形成顶部快捷入口与空状态主入口双入口。
- Viewer 不显示按钮，继续展示“请联系管理员或编辑者”的只读说明。
- 不新增账号创建 API、不改变默认目标、指标权重或动态基准。

## 6. 错误处理与数据边界

- 会话验证失败不删除团队、成员或会话数据库记录。
- 不根据团队名称搜索、匹配或自动加入团队。
- 不自动选择其他工作区；恢复记录和服务端上下文不一致时按失效处理。
- 创建账号入口仍受现有 Admin/Editor 权限和服务端鉴权控制，前端按钮不替代权限校验。
- 本次不清理用户已重复创建的团队，避免误删真实数据。

## 7. 验收

1. 创建团队后关闭当前标签页，再从同一浏览器打开 `/enter`，能够返回原工作区。
2. Docker Compose 正常重启且保留卷后，仍能返回同一工作区，工作区和成员 ID 不变。
3. 邀请码加入的成员也具备相同的同浏览器恢复行为。
4. 伪造、损坏、过期、撤销或跨工作区恢复记录不会进入工作台。
5. 临时网络失败保留恢复记录并可重试，不自动跳转到创建团队。
6. 无账号 Admin/Editor 首页显示“创建账号”，点击后直接打开账号创建面板。
7. Viewer 首页不显示创建账号操作。
8. Web 专项测试、Web 全量测试、ESLint、TypeScript 和生产构建通过。
9. 使用保留数据卷的本地环境完成重启与浏览器验收，不删除现有用户数据。

## 8. 非目标

- 不实现跨设备登录、管理员恢复码、邮箱、手机号、账号密码或第三方登录。
- 不延长现有 14 天团队会话期限。
- 不合并或删除已有重复工作区。
- 不修改平台账号数据模型、API 或数据库迁移。
