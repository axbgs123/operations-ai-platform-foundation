# 运营 AI 工作台前端重设计规格

日期：2026-07-29

状态：设计完成，用户授权自主完成设计与复核

产品基线：`docs/superpowers/specs/2026-07-20-operations-ai-platform-design.md`

实施优先级：秋招作品集 > GitHub 开源 > 真实团队长期使用

## 1. 背景与问题

当前后端业务能力和自动化验收已经较完整，但前端页面主要以互相独立的全屏页面存在。工作区页面缺少统一外壳、稳定主导航、面包屑、账号上下文和模块间返回关系，导致以下问题：

1. 用户无法持续判断“当前位于哪个工作区、账号、内容和步骤”。
2. 内容、分析、生成、事实、风格和风控虽然已经实现，但入口分散且容易被忽略。
3. 从列表、图表或队列下钻后，返回时容易丢失筛选和分页上下文。
4. 当前大面积深色卡片缺少清晰的信息层级，不像成熟的运营 SaaS 工作台。
5. 导出备份、回收站、模型配置、后台任务等已实现能力缺少统一可发现入口。
6. 全部账号视图和单账号指标视图缺少明确边界，容易让用户误以为抖音与小红书可以合并计算。
7. 非开发者 Task 9B 测试已经准备，但在已知导航缺陷修复前继续测试只会重复确认已知问题。

本次重设计不改变业务规则、数据模型、安全边界或产品范围。目标是重新组织现有能力，并补齐必要的前端聚合页面和只读聚合 API，使已实现功能可发现、可理解、可连续完成。

## 2. 设计目标

### 2.1 核心目标

1. 所有私有工作区页面使用同一套工作台外壳。
2. 所有主要业务模块最多通过两次明确点击到达。
3. 用户始终能看到工作区、角色、平台、账号和页面层级。
4. 工作台、单账号仪表盘和单条内容详情形成明确的三级范围。
5. 全部账号视图不合并不同平台或账号的业务指标。
6. 分析和风控采用“全局发现、单条处理”的双入口结构。
7. 生成流程按原始业务闭环连续展示，不能把事实确认、风格、爆款和风控拆成孤立功能。
8. 所有已实现但隐藏的管理能力获得清晰入口。
9. 桌面端支持完整功能；手机端支持查看、确认、反馈和轻量待办。
10. 重设计完成后重新执行独立非开发者 Task 9B 测试。

### 2.2 非目标

1. 不修改动态基准、事实冲突、RiskRAG、生成或权限的业务算法。
2. 不接入真实抖音、小红书页面。
3. 不执行真实千问调用。
4. 不增加自动发布能力。
5. 不开发严格 A/B 实验。
6. 不在本阶段提供深色模式。
7. 不为了视觉效果隐藏错误、证据、样本不足或免责声明。
8. 不把工作区级汇总变成跨平台综合运营分数。

## 3. 已批准设计决策

1. 产品形态：模块化运营工作台。
2. 主导航：左侧分组导航。
3. 侧边栏：默认展开，可手动折叠并保存个人偏好。
4. 默认数据范围：全部账号。
5. 全部账号页面：只聚合状态、待办、完整度和闭环，不合并指标趋势。
6. 单账号页面：展示该平台账号的目标指标、趋势、动态基准和内容分布。
7. 内容详情：完整页面，内部使用标签切换。
8. 分析和风控：保留全局入口及单条内容入口。
9. 首页：运营指挥台，兼顾状态、问题和行动。
10. 视觉方向：明亮专业 SaaS。
11. 响应式：桌面优先；手机支持查看与轻量处理，复杂编辑提示使用桌面端。
12. 重设计范围：全部私有工作区页面统一完成后再进行 Task 9B。

## 4. 信息架构

### 4.1 稳定范围层级

产品范围固定为：

> 工作区 → 平台账号 → 栏目/活动 → 单条内容 → 数据快照/分析/扫描/生成记录

页面层级分为：

1. 工作区级：跨账号运营状态、待办、资产和治理。
2. 账号级：同平台、同账号的指标、动态基准和配置。
3. 栏目级：账号配置的临时覆盖和活动范围。
4. 内容级：当前内容的快照、分析、风控和生成记录。

任何页面不得通过视觉布局暗示抖音和小红书指标可以混算。

### 4.2 左侧导航

#### 工作台

- 工作台总览

#### 内容运营

- 账号仪表盘
- 栏目与活动
- 内容库
- 数据导入
- 分析中心

#### 策略资产

- 爆款素材库
- 账号风格
- 事实资料

#### AI 创作

- 生成中心
- 发布前检查

#### 治理与数据

- 风控知识库
- 导出与备份
- 回收站

#### 工作区管理

- 后台任务
- 工作区设置

### 4.3 角色可见性

管理员：

- 可见全部导航。
- 可管理成员、邀请码、模型、账号配置、指标、风控知识、导出恢复、保留和删除。

编辑者：

- 可见工作台、内容运营、策略资产、AI 创作、允许的导出和后台任务状态。
- 不能管理模型密钥、成员权限或工作区删除。

查看者：

- 可见只读工作台、账号仪表盘、内容、分析、已确认资产、生成结果和安全状态。
- 不展示不可执行的写操作；必要时显示权限说明，不显示虚假可点击按钮。

Demo：

- 使用同一视觉体系，但显示固定“示例工作区 · 只读”横幅。
- 不展示真实配置入口、上传入口、删除入口或付费模型入口。
- 公开 Demo 与私有工作区资源完全隔离。

### 4.4 顶部栏

顶部栏固定包含：

1. 面包屑。
2. 平台筛选器。
3. 账号筛选器。
4. 当前角色和成员菜单。
5. 帮助入口。
6. 在存在失败后台任务时显示安全任务状态提示。

平台和账号筛选使用 URL query 保存。跨模块跳转时，在目标模块支持相同范围的前提下保留筛选；不支持时明确重置并显示原因。

默认值为“全部平台、全部账号”。此时不显示跨平台指标合计或趋势，只显示账号卡片和运营状态。

### 4.5 规范路由

所有私有页面使用 `/workspaces/{workspace_id}` 作为共同前缀。规范路由如下：

| 模块 | 规范路由 |
| --- | --- |
| 工作台总览 | `/workspaces/{workspace_id}` |
| 账号列表 | `/workspaces/{workspace_id}/accounts` |
| 单账号仪表盘 | `/workspaces/{workspace_id}/accounts/{account_id}` |
| 栏目与活动 | `/workspaces/{workspace_id}/columns` |
| 内容库 | `/workspaces/{workspace_id}/contents` |
| 单条内容详情 | `/workspaces/{workspace_id}/contents/{content_id}?tab={tab}` |
| 数据导入 | `/workspaces/{workspace_id}/imports` |
| 分析中心 | `/workspaces/{workspace_id}/analysis` |
| 爆款素材库 | `/workspaces/{workspace_id}/viral-library` |
| 账号风格 | `/workspaces/{workspace_id}/styles` |
| 事实资料 | `/workspaces/{workspace_id}/facts` |
| 生成中心 | `/workspaces/{workspace_id}/generation` |
| 发布前检查 | `/workspaces/{workspace_id}/preflight` |
| 风控知识库 | `/workspaces/{workspace_id}/risk-knowledge` |
| 导出与备份 | `/workspaces/{workspace_id}/data-management/exports` |
| 回收站 | `/workspaces/{workspace_id}/data-management/trash` |
| 后台任务 | `/workspaces/{workspace_id}/settings/jobs` |
| 工作区设置 | `/workspaces/{workspace_id}/settings` |

内容详情的合法 `tab` 固定为 `overview`、`snapshots`、`analysis`、`risk` 和 `generation`。未知标签回退到 `overview`，不能渲染空白页面。

已有公开 Demo、进入工作区和邀请链接保持兼容。已有私有深链接通过受控重定向或兼容路由进入新规范路由；迁移时保留工作区和资源 ID，不接受外部 `returnTo`。在所有内部链接和自动化测试迁移完成前，不删除旧路由兼容层。

## 5. 全局工作台外壳

### 5.1 桌面布局

- 展开侧边栏宽度：240px。
- 折叠侧边栏宽度：72px。
- 顶部栏高度：56px。
- 内容区域背景：浅灰中性底色。
- 内容面板：白色，低阴影或无阴影，以边框区分层级。
- 最大内容宽度按页面类型决定：
  - 仪表盘和表格：流式使用可用宽度。
  - 表单和阅读型页面：限制在 960—1120px。
  - 封面编辑器：使用可用宽度并允许折叠侧栏。

侧边栏折叠偏好按成员保存在浏览器本地展示偏好中，不包含业务数据或秘密。折叠后图标必须有 Tooltip 和可访问名称。

### 5.2 手机布局

- 小于 768px 时侧边栏变为抽屉。
- 顶部保留页面标题、账号范围和菜单按钮。
- 数据表转换为重点字段卡片或支持横向滚动，不能截断关键状态。
- 手机允许：
  - 浏览工作台和账号状态。
  - 查看内容和分析。
  - 提交有用/无用反馈。
  - 确认截图候选和低风险轻量操作。
  - 查看任务和风控状态。
- 手机不承担：
  - 大型 Excel 映射。
  - 完整模型和工作区配置。
  - ZIP 恢复。
  - 封面精细编辑。
  - 复杂知识库审核。
- 不支持的操作显示明确说明和“在电脑端继续”，不能静默隐藏。

## 6. 核心页面设计

### 6.1 工作台总览

范围：工作区。

首屏结构：

1. 数据状态：
   - 有多少账号缺少推荐快照。
   - 有多少导入等待确认。
   - 数据完整度按账号分别展示。
2. 待处理问题：
   - 待分析内容。
   - 高风险草稿。
   - 低置信度 OCR。
   - 失败或需要配置的任务。
3. 下一步行动：
   - 只突出当前最高优先级行动。
   - 显示预计操作时间，但不得把未经真实验证的时间当作承诺。
4. 账号卡片：
   - 平台、账号名、数据完整度、待分析数量、有效闭环状态。
   - 点击进入单账号仪表盘。
5. 快捷操作：
   - 新建内容。
   - 导入数据。
   - 查看分析队列。
   - 进入生成中心。

全部账号状态下禁止显示：

- 合并播放量/曝光量。
- 跨平台平均点击率。
- 跨账号动态基准。
- 跨平台综合趋势。

### 6.2 账号仪表盘

范围：单个平台账号。

页面顶部固定显示：

- 平台。
- 账号。
- 内容类型。
- 数据成熟度。
- 基准范围。
- 实际样本数。
- 数据完整度。

页面按照“状态 → 问题 → 原因 → 行动”组织：

1. 4—6 个目标指标卡。
2. 一张账号趋势图。
3. 中位数、前25%、前10%基准区间。
4. 爆款候选与异常内容。
5. 原因假设与置信度。
6. 下一步行动列表。

用户可以隐藏不关注的非必要模块。该偏好只影响展示，不改变指标计算、告警、风险门禁或其他成员看到的内容；必须保留“恢复默认布局”入口。

图表门禁：

- 一条快照：只显示当前数据卡。
- 两条以上有效快照：允许显示增长趋势。
- 缺少曝光与阅读/播放必要字段：不显示漏斗图。
- 发布时间样本不足：不显示热力图。
- 样本少于5条：只展示原始值。
- 5—9条：显示低置信度。
- 10条以上：允许正常分位分析。

任何隐藏图表的位置都显示“为什么没有图表”和缺少什么数据。

### 6.3 内容库

内容库采用完整列表页面，不使用永久分栏详情。

列表顶部：

- 平台、账号、栏目、内容类型、状态、成熟度筛选。
- 搜索标题。
- 排序。
- 保存到 URL 的筛选状态。
- 新建内容和导入数据主操作。

列表行/卡片展示：

- 封面缩略图。
- 标题。
- 平台和账号。
- 栏目/活动。
- 内容生命周期状态。
- 发布时间。
- 最新快照成熟度。
- 数据完整度。
- 分析状态。
- 风控状态。
- 下一步操作。

移动端转换为内容卡片，不在狭窄表格中压缩全部列。

### 6.4 单条内容详情

页面顶部：

- 面包屑。
- 返回内容列表。
- 内容标题。
- 平台、账号、栏目。
- 生命周期状态。
- 生成同类内容主操作。
- 更多操作菜单。

生命周期：

> 灵感/选题 → AI生成 → 人工编辑 → 待审核 → 已发布 → 数据采集中 → 已分析 → 可复用

详情标签：

1. 概览
   - 标题、文案、封面、链接、发布时间、来源和当前状态。
   - 发布时配置版本。
   - 当前下一步。
2. 数据快照
   - 追加式快照时间线。
   - 指标值、来源、识别置信度和确认状态。
   - 满足条件时显示单条趋势。
3. 分析
   - 状态、问题、原因、行动。
   - Evidence 引用。
   - 样本、基准、置信度。
   - 有用/无用、保存建议和采用状态。
4. 风控
   - 标题、文案、封面 OCR 联合扫描。
   - 确定性规则、RAG 辅助、引用和历史扫描。
   - 固定免责声明。
5. 生成记录
   - 关联生成运行。
   - 模型、风格、事实、爆款和预设版本。
   - 原始结果、最终采用结果和修改幅度。

从分析队列、风险队列或图表下钻进入详情时，返回操作必须恢复来源页的筛选、分页和排序。

## 7. 业务模块页面

### 7.1 栏目与活动

栏目与活动独立于账号设置展示，以避免临时覆盖功能被隐藏。

页面内容：

- 栏目/活动列表。
- 所属账号和平台。
- 有效时间。
- 当前状态。
- 继承的账号配置。
- 已覆盖项数量。
- 目标、权重、基准、风格和生成预设覆盖。

编辑界面必须逐项显示：

- 继承账号默认。
- 临时覆盖。
- 覆盖结束后恢复账号默认。
- 当前生效版本。

### 7.2 数据导入

使用统一导入中心，包含四个明确入口：

1. 手动录入。
2. Excel/CSV。
3. 截图识别。
4. Capture Extension。

页面结构：

- 导入方式卡片。
- 当前暂存批次。
- 新增、更新、疑似重复、失败统计。
- 字段预览和错误原因。
- 人工确认。
- 历史导入任务。

所有方式遵循：

> 选择来源 → 上传/采集 → 暂存预览 → 修正 → 确认入库

低置信度、未知字段和重复项不得通过视觉设计弱化。

### 7.3 分析中心

范围：工作区级发现与筛选。

包含：

- 待分析。
- 分析中。
- 已完成。
- 样本不足。
- 失败/需配置。
- 建议待采用。

每条队列项显示：

- 内容。
- 平台、账号和栏目。
- 数据成熟度。
- 样本数。
- 分析版本。
- 当前问题和置信度。
- 下一步。

点击进入单条内容的“分析”标签。

### 7.4 爆款素材库

只展示人工确认进入素材库的内容。

页面内容：

- 候选与已确认分区。
- 流量、互动、涨粉和转化类型。
- 基准范围、样本数、分位和推荐原因。
- 人工确认人和时间。
- 适用账号、栏目和场景。
- 生成引用次数。

候选不得通过视觉样式伪装成已确认素材。

### 7.5 账号风格

默认先选择账号；栏目/活动覆盖通过二级范围切换。

三个独立分区：

- 标题风格。
- 文案风格。
- 封面风格。

每个分区包含：

- 当前版本。
- 代表内容。
- 提取特征。
- 禁止项。
- 最近更新时间。
- 是否被栏目临时覆盖。

不得把爆款自动作为风格样本。页面需要明确区分“账号风格”和“爆款结构”。

### 7.6 事实资料

页面采用来源列表与事实清单两级结构。

来源列表显示：

- 文档、图片、链接或文字。
- L1—L5 等级。
- 解析状态。
- 确认状态。
- 冲突数量。
- 生效范围。

事实清单显示：

- 字段和值。
- 来源位置。
- 来源等级。
- 用户确认状态。
- 冲突。
- 覆盖记录。
- 禁止视觉推测标识。

颜色不能作为唯一状态表达；等级和冲突必须有文本。

### 7.7 发布前检查

这是运营队列，不是风控知识管理。

包含：

- 待扫描。
- 高风险阻断。
- OCR低置信度。
- 无有效RAG证据。
- 已修改待复检。
- 已通过人工确认。

点击进入单条内容“风控”标签。

## 8. 生成中心连续流程

生成中心使用桌面端五步向导，而不是把所有字段堆在一页。

### 第一步：范围与目标

- 平台。
- 账号。
- 栏目/活动。
- 运营目标。
- 当前生效配置版本。

### 第二步：事实资料

- 上传文档、图片、链接或文字。
- 选择已有事实来源。
- 发起明确的联网事实检索；联网结果以L4候选来源展示，保存网页、发布时间和访问时间，具体参数仍需人工确认。
- OCR/解析状态。
- 事实清单确认。
- 冲突处理。
- 允许无资料继续，但显示醒目提示。

事实未确认或存在高风险冲突时不能进入实际生成。

### 第三步：风格与参考

- 标题风格继承，默认开启。
- 文案风格继承，默认开启。
- 封面风格继承，默认开启。
- 栏目覆盖状态。
- 0—3条人工确认爆款参考。
- 参考图及构图、风格、人物、产品、配色用途。
- 自定义提示词。
- 生成预设。

### 第四步：生成与编辑

- 多个标题建议。
- 可编辑文案。
- 四种封面模式：
  - 模板。
  - AI视觉。
  - 混合。
  - 自定义。
- 后台任务状态。
- Mock/真实Provider和experimental状态。
- 数据发送和费用提示。

复杂封面编辑在手机端只读，并提示桌面端继续。

### 第五步：复核与保存

- 事实一致性结果。
- 标题、文案、封面联合风控。
- OCR置信度。
- 引用和免责声明。
- 修改后复检。
- 保存草稿。
- 记录采用状态和修改幅度。

页面右侧在桌面端固定显示“本次生成摘要”，包含账号、栏目、目标、事实、风格、爆款、模型和风险状态。不得显示密钥或Provider Workspace ID。

## 9. 治理与数据页面

### 9.1 风控知识库

管理员使用。

页面分为：

- 文档列表。
- 生命周期。
- 版本链。
- Chunks和引用检查。
- 反馈审核。
- 规则更新候选。
- 固定Mock评估。

抖音和小红书使用显式平台标签和独立筛选，不能在同一表格中省略平台。

### 9.2 导出与备份

页面通过任务卡片区分：

- CSV内容与运营数据。
- Markdown单条分析报告。
- JSON轻量备份。
- ZIP完整备份。
- JSON恢复预览。
- ZIP恢复。

每个任务显示：

- 范围。
- 包含项。
- 排除项。
- 状态。
- 创建时间。
- 过期时间。
- 下载或确认操作。

恢复流程必须显示新增、覆盖、跳过和冲突，不使用模糊的“一键恢复”。

### 9.3 回收站

- 只展示支持软删除的内容资源。
- 显示可恢复截止时间。
- 显示保留策略和证据保留阻断。
- 最终删除使用二次确认。
- 工作区删除与普通回收站分开，位于工作区设置的危险操作区。

### 9.4 后台任务

- 类型、状态、时间筛选。
- 任务阶段。
- 安全错误码。
- 取消和有限重试。
- compensation_required。
- dead-letter等价状态。
- PostgreSQL、Redis、S3 readiness。

Editor只读，Admin可执行允许的运维操作。

### 9.5 工作区设置

使用设置页内部二级导航：

- 工作区概览。
- 成员与邀请码。
- 平台账号配置。
- 指标、目标与基准。
- 模型配置与预算。
- 保留策略。
- 危险操作。

模型密钥输入不回显、不持久化到浏览器；页面不提供base URL输入。

## 10. 视觉设计系统

### 10.1 色彩

- 页面背景：`#F5F7FB`。
- 主面板：`#FFFFFF`。
- 主文本：`#1B2430`。
- 次级文本：`#6F7B89`。
- 边框：`#E2E6EC`。
- 主强调：低饱和紫色，建议基准 `#6D55DC`。
- 成功：绿色。
- 警告：琥珀色。
- 错误/高风险：红色。
- 信息：蓝色或青色。

状态颜色必须同时配合文本、图标或标签，不能仅依赖颜色。

### 10.2 字体与密度

- 使用系统中文字体栈，不引入外部在线字体。
- 页面标题：24px左右。
- 区块标题：16—18px。
- 正文：14px。
- 辅助文字：12px。
- 表格行高：44—52px。
- 表单控件高度：40px。
- 卡片圆角：8—12px，不使用过度巨大的圆角。
- 页面区块间距：24px。
- 卡片内部间距：16—20px。

### 10.3 组件层级

统一组件：

- WorkspaceShell。
- SidebarNav。
- WorkspaceTopbar。
- Breadcrumbs。
- ScopeFilters。
- PageHeader。
- StatusBadge。
- MetricCard。
- EmptyState。
- ErrorState。
- PermissionNotice。
- TaskStatus。
- DataTable。
- FilterBar。
- DetailTabs。
- ConfirmDialog。
- MobileDrawer。
- DesktopOnlyNotice。

按钮层级：

1. 每页最多一个主要按钮。
2. 次要按钮使用描边或普通文本样式。
3. 危险操作只能使用红色并配二次确认。
4. “更多操作”只收纳低频操作，不得隐藏核心下一步。

## 11. 页面状态

每个业务页面必须设计：

1. 加载：
   - 使用与最终布局一致的Skeleton。
2. 空状态：
   - 说明为什么为空。
   - 给出一个明确下一步。
3. 样本不足：
   - 显示当前样本和所需样本。
   - 不显示误导图表。
4. 权限不足：
   - 显示当前角色和所需角色。
   - 不暴露资源是否存在。
5. 模型未配置：
   - 数据功能可继续使用。
   - AI操作显示配置说明。
6. Provider experimental：
   - 显示真实验证状态和数据发送提示。
7. 任务失败：
   - 显示安全错误码、阶段和允许的下一步。
8. 无有效RiskRAG证据：
   - 保留确定性结果。
   - 显示`NO_ACTIVE_RISK_EVIDENCE`对应说明。
9. 网络或依赖不可用：
   - 不丢失已填写输入。
   - 不伪装为业务成功。

## 12. 导航与返回规则

1. 所有工作区业务页面必须位于共享layout下。
2. 每个页面有唯一主导航归属。
3. 单条内容的分析、风控和生成记录不在侧边栏重复为详情页面。
4. 全局分析和发布前检查只负责队列与筛选。
5. 从全局队列进入详情时携带`returnTo`或受控查询上下文。
6. `returnTo`只能指向当前工作区内允许的应用路由，禁止开放重定向。
7. 浏览器前进后退必须恢复URL中的筛选。
8. 深链接直接打开时仍显示完整工作区外壳和面包屑。
9. 工作区切换后清除不兼容的账号、栏目和内容范围。
10. 被撤销成员在下一次请求后返回安全入口，不保留私有页面内容。

## 13. 前端与API边界

业务规则继续位于API层。

允许为重设计新增：

- 工作台聚合只读接口。
- 账号列表与状态聚合接口。
- 分析队列只读接口。
- 发布前检查队列只读接口。
- 导出/恢复任务列表接口。
- 导航徽标计数接口。

这些接口只能聚合已有受控数据，不得复制基准、分析、事实或风控算法。

前端不得：

- 自行计算动态基准。
- 混算平台指标。
- 自行判定爆款。
- 自行调整事实优先级。
- 自行降低风险严重度。
- 在客户端解密模型配置。

## 14. 可访问性

1. 所有导航、标签、弹窗和表单可使用键盘操作。
2. 焦点样式清晰可见。
3. 颜色对比满足WCAG AA目标。
4. 图标按钮有可访问名称和Tooltip。
5. 图表提供文本摘要或数据表替代。
6. 错误与状态更新使用合适的ARIA live区域。
7. 弹窗锁定焦点并在关闭后返回触发元素。
8. 移动抽屉打开时背景不可交互。
9. 动画尊重`prefers-reduced-motion`。
10. 不依赖悬停才能访问必要信息。

## 17. 验收标准

### 17.1 信息架构

1. 所有私有工作区页面均使用统一外壳。
2. 原设计文档第6节的主模块均有明确入口。
3. 不存在只能通过手输URL访问的正式功能页面。
4. 核心流程不依赖“更多操作”发现。
5. 全局和详情双入口范围明确。

### 17.2 数据正确性

1. 全部账号视图不混算平台指标。
2. 单账号仪表盘保留平台、内容类型、成熟度和基准范围。
3. 样本不足和缺少快照时正确降级。
4. 历史分析与生成版本可追溯。
5. 前端不复制API业务规则。

### 17.3 可用性

1. 非开发者无需主持人代操作即可找到主要模块。
2. 能解释“工作台、账号仪表盘、内容详情”的范围区别。
3. 能从导入完成到分析、建议和草稿保存。
4. 能找到事实、风格、爆款和风控状态。
5. 能从详情返回原队列且筛选不丢失。
6. 能理解Demo只读、Mock模型和风控免责声明。

### 17.4 工程质量

1. API、Web、Extension和E2E回归通过。
2. OpenAPI和TypeScript无漂移。
3. 无新增秘密或真实私有数据。
4. 无Critical/Important代码审查问题。
5. 桌面与手机关键路径通过自动化。
6. Task 9B重新执行并保留真实匿名证据。
