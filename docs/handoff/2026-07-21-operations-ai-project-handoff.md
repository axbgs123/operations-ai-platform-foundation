## 已确认的重要决定

- 产品面向 3—10 人运营团队，支持抖音和小红书，指标、基准和分析完全分离。
- 产品能力跨赛道通用，首个验证对象是 AI 科技内容运营团队；服装账号用于事实一致性扩展案例。
- 产品核心闭环是：内容生产 → 发布记录 → 数据采集 → 动态分析 → 爆款确认 → 策略复用 → 新内容生成。
- 首期形态为公开 Web 产品；后续可以扩展桌面客户端、App 和本地 Agent。
- 平台数据入口包括手动、Excel/CSV、截图上传和 Chrome/Edge 运营数据采集扩展。
- 数据节点 1 小时、24 小时、72 小时、7 天只是推荐，不强制。
- 默认展示流量、互动、涨粉、转化四维表现；综合指数只是可选排序工具。
- 爆款只表示当前账号、当前样本范围内的候选，进入素材库必须人工确认。
- 生成标题、文案和封面时默认沿用账号历史风格，但可以分别关闭。
- 生成前支持文档、图片、链接、联网搜索和文字资料；上传资料后必须确认事实清单。
- 事实来源使用 L1—L5 可信等级，视觉模型不得单独推断面料、价格、功效、认证等确定性事实。
- 平台风控使用规则检测＋RAG，抖音和小红书分库，公共与私有规则分层并具备审核、版本、更新和评估机制。
- 浏览器能力正式名称是“运营数据采集扩展”，不是桌面 Agent。
- 扩展包含默认安全确认模式和用户主动开启的一键采集模式；一键模式仍需确认识别数据后才能入库。
- 私有工作区不要求邮箱注册，每位成员拥有独立邀请码和角色，可单独撤销并审计。
- JSON 只做轻量结构备份；ZIP 才是包含媒体和知识文档的完整备份。
- 模型架构允许扩展多个供应商，但首个正式版本只承诺一套经过完整验证的默认组合。
- 仪表盘按照“状态—问题—原因—行动”组织，图表只在数据条件满足时出现。
- 北极星指标是“每周完成的有效运营闭环数”。

## 技术方向

已经确认的总体技术方向：

- 单仓库、模块化单体。
- Web：React/Next.js。
- API 与 AI/数据任务：Python/FastAPI。
- 数据库：PostgreSQL，风控知识库使用向量能力。
- 文件：S3 兼容对象存储。
- 后台任务与缓存：Redis 队列。
- 数据采集：Chrome/Edge Manifest V3 扩展。
- 部署：Docker Compose 本地启动并支持云服务器。
- 后续 App 和桌面端复用同一后端 API。

技术选型的具体版本尚未确定。制定开发计划时应核对当前官方文档，不要凭旧记忆指定版本。
