# ADR 0001：采用模块化单体作为产品基础架构

状态：已接受（2026-07-21）

## 背景

产品需要在同一套工作区内承载账号配置、作品资料、运营数据、诊断、生成、平台风控知识和未来的桌面 Agent。第一阶段由小团队快速迭代，同时必须保证数据隔离、可测试和后续可拆分。

## 决策

采用模块化单体：Next.js Web 负责交互，FastAPI 负责业务 API，Celery 负责异步任务；PostgreSQL 是业务事实来源，Redis 只承载缓存和队列，MinIO/S3 保存素材对象。

后端按业务域组织模块。模块拥有自己的路由、服务、模型和测试，通过明确的服务接口协作，不跨模块直接拼接私有查询。当前核心域为 `workspace`、`demo` 和 `content`，诊断、生成、知识库将在同一约束下扩展。

API 的 OpenAPI 文档是前后端合同。`packages/shared-schemas` 自动生成 TypeScript 类型，CI 检查生成结果是否漂移；前端不再手写重复响应模型。

## 理由

- 一个部署单元和一套事务边界适合早期快速交付，也降低个人维护成本。
- 模块边界和工作区隔离规则提前固化，避免代码随功能增长变成无边界单体。
- Celery、对象存储及版本化配置已经提供未来耗时 AI 任务和 Agent 操作所需的扩展点。
- 若某个域未来在负载、发布频率或团队归属上需要独立，可从服务接口处拆分，而不是现在承担微服务的运维复杂度。

## 后果

所有模块共享数据库进程，因此代码审查与架构测试必须阻止跨工作区查询和跨域耦合。桌面客户端或电脑操作 Agent 应继续调用版本化 API；本地截屏能力通过受控桥接进程接入，不把桌面权限放入 Web 服务。
