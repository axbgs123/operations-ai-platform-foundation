# 工作区数据隔离约束

真实工作区是系统的安全边界。除公开 Demo 种子外，每一条业务记录都必须能追溯到 `workspace_id`，所有读取和修改都同时校验当前会话成员与目标工作区。

## 强制规则

1. 私有表必须直接包含 `workspace_id`，或通过受约束的父记录唯一归属工作区。服务查询不能只使用资源 ID。
2. 跨工作区访问统一返回 404，避免泄露资源是否存在；角色权限不足返回 403。
3. 邀请码只保存 Argon2 哈希；会话只保存随机令牌摘要。写请求同时要求 HttpOnly 会话 Cookie 与 CSRF 令牌。
4. 对象键包含工作区和作品前缀。上传、确认、下载都重新校验成员关系；签名 URL 有短有效期，数据库不保存永久公开地址。
5. 公开 Demo 使用固定的合成数据和独立会话限额，不允许上传，也不能写入真实工作区表。
6. 删除作品采用软删除，历史发布快照和所用目标/基准配置版本继续保留，便于审计与复盘。

## 测试门禁

集成测试必须覆盖两个工作区访问同一资源时的 404、不同角色的写权限、Demo 与真实数据隔离、对象上传确认以及删除后行为。OpenAPI 合同、迁移状态和 foundation 浏览器冒烟都在 CI 中执行。

新增模块若不能说明其 `workspace_id` 来源、授权入口、对象键规则和跨租户测试，不得进入主分支。
