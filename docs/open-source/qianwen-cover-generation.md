# 千问封面生成、数据发送与对象生命周期

封面有 `template`、`ai_visual`、`hybrid`、`custom` 四种模式。template 完全在本地
生成；其余模式可调用工作区配置的千问图片模型。千问只生成背景和主体层，中文标题、
副标题、品牌名、Logo 与安全区由本地程序化布局完成。人物、商品、颜色、面料、Logo
和构图仍必须由用户在 Web 中人工确认。

## 会发送什么

真实模式会向用户选择地域的阿里云百炼发送业务 Prompt，以及零至三张由用户明确
授权为 Provider 输入的参考图。发送前会校验工作区和内容归属、对象状态、固定版本、
实际 MIME、文件大小、宽高和总像素，并重新编码以移除 EXIF、GPS 和不必要元数据。
Logo 不发送。界面应在调用前披露 Provider、模型、地域、参考图数量和用途，以及可能
产生费用。

不会发送或保存到模型请求中的内容包括：其他工作区资产、已删除/隔离/待清理资产、
任意用户 URL、对象存储凭据、浏览器 Cookie、邀请码、会话/扩展令牌或模型密钥。
Base64 参考图仅存在于一次 Adapter 调用内存，不进入任务参数、日志、数据库或备份。

## 结果与保留

供应商临时 URL 不返回前端、不持久化。下载结果通过 SSRF、MIME、大小、静态图片、
像素和目标尺寸校验后重新编码为 PNG，先写入
`workspaces/{workspace}/generated-covers/{run}/{attempt}/` 隔离前缀。程序化排版与
OCR/RiskRAG 记录完成后，最终对象才成为受控引用。

对象存储与数据库不能形成同一事务。若任一发布步骤失败，任务不会标记成功，已写
对象登记到现有 `managed_objects` 清理队列；取消任务会把未发布对象安排为立即
清理。成功结果只通过受权限保护的业务流程访问。工作区删除会将相关结构化记录和
受控对象纳入原有删除与残留检查。

## 费用、不确定结果与人工重试

一次图片生成最多发起一次 Provider POST，不执行 Celery 或普通 HTTP 自动重试。
超时、断线或结果无法确认时状态为 `provider_outcome_unknown`，因为请求可能已经
计费。admin/editor 必须明确创建新的人工重试 attempt；新 attempt 不覆盖旧历史，
并可能产生重复费用。

## 风控与当前验证边界

最终 PNG 必须经过 OCR/RiskRAG 门禁。OCR 低置信度或不可用时强制人工复核；高风险
结果不得进入待发布状态。固定提示为：“辅助判断，不保证通过平台审核”。

普通测试只使用人工合成图片、固定 Mock 和 MockTransport，不访问真实千问或平台，
不产生费用。真实鉴权、真实图片效果、地域可用性、延迟、限流、费用、内容审核行为
和实际保留行为仍未验证；不能据此声称生产可用或保证平台审核通过。
