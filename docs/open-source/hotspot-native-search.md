# 热点截图与模型原生联网创作

该流程把公开热点榜截图作为选题线索，不把 OCR 结果直接当成事实：

1. 用户在公开 HTTPS 热点榜页面主动使用浏览器扩展截图，并选择抖音或小红书。
2. Web 工作台展示 OCR 候选，管理员或编辑者人工确认后生成不可覆盖的热点快照。
3. 用户选择同平台账号，系统使用该工作区已经通过连接检测的文字模型原生联网能力核实热点。
4. 联网结果必须带真实 HTTPS 引用；生成候选只能引用本次研究返回的 URL。
5. 用户可把候选保存为普通内容草稿，继续执行事实核验、风控扫描和人工复核。保存不等于发布。

运营智能体保留原有账号分析、计划、确认和导出能力，同时可以读取已确认热点并触发上述研究流程。对话记录会保存，但 API Key、Prompt、网页正文和截图正文不会写入聊天消息。

## Provider 边界

- 当前真实联网仅支持已经完成原生联网能力检测的千问文本配置。
- 调用的是模型供应商托管的 `web_search` 与 `web_extractor` 工具，不需要另外配置搜索 API。
- 通用 OpenAI-compatible 文本端点不会被假定具备联网能力，也不会静默改用其他搜索服务。
- Mock 模式只验证工程流程，返回合成来源，不能作为真实热点研究或事实依据。

## 已知限制

- 截图可能遗漏、识别错误或过时，必须由用户确认。
- 模型联网结果仍可能不完整，引用只证明结果来自相应网页，不证明结论绝对正确。
- 保存的热点草稿仍需在内容详情和发布前检查中完成事实与风险复核。
- 当前没有自动定时抓榜、自动发布或平台账号自动操作。
