运营内容智能分析与生成平台：跨平台便携 Docker 包
================================================

一、运行前准备

1. 安装并启动 Docker Desktop，确认其中包含 Docker Compose v2。
2. 建议至少有 8 GB 物理内存和 10 GB 可用磁盘空间。
3. 首次启动需要网络访问容器镜像与依赖源，通常需要 5–15 分钟。
4. 默认端口为：
   - Web：3000
   - API：8000
   - PostgreSQL：55432
   - 对象存储：9000
   - 对象存储控制台：9001
   端口冲突时请先停止占用程序，启动器不会自动终止其他进程。

二、启动与停止

macOS：
- 解压后双击“启动运营工具-macOS.command”。
- 若系统阻止首次运行，可在“系统设置 → 隐私与安全性”中确认后重试。
- 正常停止请双击“停止运营工具-macOS.command”。

Windows：
- 解压后双击“启动运营工具-Windows.bat”。
- 正常停止请双击“停止运营工具-Windows.bat”。
- 当前 Windows + Docker Desktop 真实运行验收状态为 not_run；静态合同通过不代表已在真实 Windows 环境验证。

启动成功后会打开：
http://127.0.0.1:3000/enter

三、首次登录与敏感信息

首次启动会创建一个可写的“本地运营工作区”。管理员邀请码只写入本机：
.local-state/首次登录信息.txt

该文件属于敏感信息，请勿上传、转发或提交到 Git。邀请码不会写入普通启动日志。首次登录后，请在成员管理中为其他使用者签发独立邀请码。

四、数据保留、备份和删除

正常停止与再次启动不会删除 PostgreSQL、Redis 或对象存储中的本地数据。停止脚本只关闭服务，不会删除 Docker 卷。

本便携包故意不提供双击“删除全部数据”功能，避免误删。需要迁移到另一台电脑时，请使用产品内的 ZIP 完整备份与恢复功能，不要复制运行中的数据库文件或 Docker 卷。

五、模型与外部服务边界

默认使用 Mock 模型，不需要千问 API Key，也不会产生模型费用。如需千问能力，请在工作区设置中自行配置密钥和预算。便携包不包含任何真实密钥、真实平台账号或真实运营数据。

六、常见问题

- Docker 缺失或未启动：启动 Docker Desktop 后重试。
- 端口冲突：检查 3000、8000、55432、9000、9001；启动器不会结束无关程序。
- 首次构建失败：确认网络和磁盘空间后重试，已有 Docker 卷会保留。
- API 或 Web 未就绪：按启动器显示的 docker compose 诊断命令查看状态和安全日志。
- 浏览器未自动打开：手动访问 http://127.0.0.1:3000/enter。
- 需要彻底删除本地数据：请先完成 ZIP 备份，再由具备 Docker 管理经验的人员按项目文档手动处理。

七、发布包完整性

正式便携包只从干净、已提交的 Git 源码树生成。发布目录同时提供：
- operations-ai-portable-<版本>.zip
- release-manifest.json
- checksums.txt

checksums.txt 中的 SHA-256 用于核对 ZIP 是否被替换或损坏；release-manifest.json 记录源码提交、固定构建时间和包内逐文件哈希。维护者可运行：

apps/api/.venv/bin/python scripts/release-security.py verify-portable-release --path <ZIP路径>

校验失败时不要继续解压或运行。构建器不会读取未跟踪文件，也不会把 .env、.local-state、数据库、备份、日志、密钥、邀请码或 .superpowers/brainstorm 打入发布包。
